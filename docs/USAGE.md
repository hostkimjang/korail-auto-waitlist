# 사용 안내

레일웨잇의 기본 사용 흐름을 설명합니다. 화면에 표시되는 좌석과 예약 정보는 공식 앱이나 홈페이지에서 최종 확인해야 합니다.

## 새 대기 만들기

1. 메뉴에서 `새 대기`를 선택합니다.
2. KTX 또는 SRT를 고릅니다. 두 운영사를 함께 선택할 수도 있습니다.
3. 출발역, 도착역, 출발일과 시간 범위를 정합니다.
4. 관심 열차의 일반실 또는 특실을 선택합니다.

열차와 좌석 등급마다 대기가 하나씩 만들어집니다. 같은 열차의 일반실과 특실을 각각 등록할 수 있습니다.
KORAIL 자동 예매는 선택한 일반실·특실의 운임 control을 누르고 예매를 요청하며, 사용자가 호차나 좌석번호를
고르는 기능은 아닙니다. 실제 호차·좌석번호는 KORAIL이 자동 배정합니다. 레일웨잇은 공식 예약 결과에서 둘 다
확인한 경우에만 배정 좌석을 표시합니다.

`입석만 가능`은 해당 좌석 등급에서 앉는 좌석은 매진이고 입석 상품만 보인다는 뜻입니다. 공식 예매 화면에서
입석을 확인하거나 취소 좌석 대기를 등록할 수 있지만, 레일웨잇은 이를 좌석 발견으로 알리거나 자동 예매하지
않습니다. `입석+좌석`은 일부 구간의 착석 좌석을 포함한 별도 상태이므로 순수 입석과 구분합니다.

모바일과 터치 태블릿에서는 출발역과 도착역을 전용 전체 화면에서 연속으로 고릅니다. 먼저 주요 역이나 지역을 탐색할 수 있고, 검색창을 누르면 가상 키보드가 열린 높이에 맞춰 결과 영역만 줄어듭니다. 출발역을 고르면 도착역 선택으로 이어지며, 선택 결과는 공식 역 ID와 함께 원래 여정 화면에 반영됩니다.

시간대 빠른 선택의 `새벽`은 `00:00–09:00`, `저녁`은 `18:00–00:00` 범위입니다. 저녁의 `00:00`은 선택한 출발일의 다음 자정을 뜻하며, 화면과 음성 안내에서 다음 날 경계임을 구분합니다.

## 홈 화면

홈에서는 지금 확인해야 할 항목과 감시 중인 대기를 볼 수 있습니다.

- `감시 중`: 좌석 상태 변화를 확인하고 있습니다.
- `좌석 확인 필요`: 최근 상태를 확정할 정보가 없습니다.
- `좌석 발견`: 공식 앱이나 홈페이지에서 다시 확인할 시점입니다.
- `결제 필요`: 예매 시도 결과 결제가 필요한 것으로 확인된 상태입니다. 실제 예약 내역과 결제기한은 공식 앱이나 홈페이지에서 확인하세요.
- `인증 필요`: 저장한 철도 계정의 로그인을 다시 확인해야 합니다.

정보가 오래됐거나 근거가 충분하지 않으면 `좌석 확인 필요`로 표시합니다.

홈의 대기에는 등록 당시 시간표 근거에 보존된 열차 종류와 열차번호를 함께 표시합니다. 예를 들어
`KTX-산천 · 193`처럼 보이며, migration 이전 대기처럼 실제 종류를 보존하지 않은 항목은 열차번호만
표시합니다. 열차번호만으로 KTX·KTX-산천·KTX-청룡을 추정하지 않습니다.

과거 운행·예매창 정보의 freshness가 끝나면 `예매창 열림` 같은 현재형 문구는 즉시 숨깁니다. 같은 시각이거나
더 최신인 정상 좌석 관측이 있고 다음 확인이 예정됐거나 처리 중이면 별도 만료 문구를 표시하지 않습니다.
활성 감시의 공식 관측 오류·결과 불명·자료 만료는 이전 운행 정보가 아직 유효해도 우선 표시합니다. 운영사
보호 대기나 유휴 상태에서 다음 관측 목표가 30초 넘게 지난 경우에도 마지막 결과가 매진인지와 무관하게
원인에 맞는 재시도·지연 안내를 표시합니다. 일시정지·결제·완료·만료 상태에서는 과거 오류·보호 대기를
현재 경고처럼 남기지 않습니다. 운행 취소·출발역 통과·예매 종료 같은 종단 사실은 `다시 확인 중`으로
바꾸지 않고 최종 사실 그대로 유지합니다.

## 대기 관리

감시 중인 항목에서 다음 작업을 할 수 있습니다.

- 잠시 멈추기
- 다시 시작하기
- 대기 취소하기
- 좌석을 발견했을 때 할 일 변경하기

홈의 휴지통은 감시와 이후 자동 예매를 중단하는 `대기 취소`이고, `내 예약`의 삭제는 이미 종료된 기록을
지우는 별도 행동입니다. 좌석 관찰 중 취소가 먼저 확정되면 그 결과로 자동 예매를 시작하지 않습니다. 반대로
운영사 예매 요청이 이미 시작됐거나 결제가 필요한 예약이 있으면 외부 요청이나 임시 예약을 소급 취소할 수
없으므로 대기 취소를 완료로 표시하지 않습니다. 이때 화면에 남은 결과를 확인하고 공식 예약 내역에서 직접
확인·결제 또는 취소하세요.

`알림만 받기`는 상태가 바뀌었을 때 알려주고 감시를 계속합니다. 실험 기능과 철도 계정 설정을 모두 마친 경우에만 제한적인 예매 시도 옵션을 사용할 수 있습니다. 자동 예매는 같은 좌석 가용 상태에서 한 번만 실행하며, 예매 시점에 좌석을 확보하지 못한 경우에는 확정적인 판매 불가 상태 뒤 좌석이 다시 가용해져야 다음 시도를 시작합니다. 공식 확인에서 결제 가능 기한 경과가 확인되거나 대상 임시 예약을 더 이상 찾지 못해 기존 결제 안내가 종료된 경우에도 감시로 돌아가지만, 이 근거만으로 결제 실패나 예약 취소를 단정하지 않습니다. 사용자 확인 재시작을 선택하지 않는 자동 흐름은 계속 가용한 같은 상태에서 바로 다시 예매하지 않으며, 보류 종료 뒤 판매 불가 상태와 그 이후의 새 가용 상태가 차례로 확인되어야 다음 자동 예매를 시작합니다.

결제 필요 상태에서는 최초 공식 확인과 별도로 후속 읽기 전용 확인을 최대 6회 수행합니다. 첫 후속 확인은
즉시 실행하고, 이후에는 30초·30초·2분·5분·10분 간격으로 제한하며 알려진 기한 도달 시 기존 최종 확인을
한 번 더 수행할 수 있습니다. 결제기한을 받지 못한 경우에는 가짜 시각을 표시하지 않고 같은 최대 6회 범위에서만
확인합니다. 과거 3회에서 멈춘 결제기한 없는 항목도 남은 확인을 재개할 수 있습니다. 정확히 일치하는
공식 내역에서 결제 완료가 확인되면 활성 예매 준비·진행·감시 중 또는 결제 필요 작업을 `완료`로 바꾸고
결제기한 안내를 제거합니다. 공식 확인 도중 작업이 일시정지·로그인 필요·운영사 제한으로 바뀐 경우에는 그
상태를 유지하되 확정 결제 근거를 저장하고 결제 안내·자동 재시도·수동 재시작을 닫습니다. 이 경합을 완료
알림으로 가장하지
않습니다. 일치하지 않거나
목록을 신뢰할 수 없으면 결제로 추정하지 않으며 결제·취소·추가 예약을 자동으로 실행하지 않습니다.
접속 중 `실시간 알림`의 같은 작업에 남아 있던 결제 필요 카드도 완료 안내로 교체된 뒤 자동으로 닫힙니다.
SSE를 놓친 경우에는 다음 대기 목록 갱신에서 exact 결제 근거가 있는 `결제 필요 → 완료` 전이를 복구합니다.
KORAIL·SRT의 모든 `요청 결과 불명확`은 공식 내역을 읽기 전용으로 확인합니다. 비공개 좌석 상관 근거가 없으면
대상 부재 같은 음성 근거만 반영하고 결제완료·결제보류로 바꾸지 않으며, 아래 근거까지 있는 경우에만 양성
결제 상태로 복구합니다.
예매 결과에는 운영사 원문 오류 대신 닫힌 원인, 마지막 공식 확인 결과와 시각, 완료한 재확인 횟수와
다음 확인 목표 시각을 표시합니다. `요청 결과 불명확`, `철도사 연결·응답 확인 불가`, `대상 없음`, `로그인 필요`,
`운영사 차단`처럼 후속 행동이 다른 상황을 구분하지만, 공식 양성 근거가 없으면 결제 실패·결제 완료·예약
취소로 바꾸지 않습니다.
공식 확인 자체가 `판단 불가`이면 다시 `공식 내역을 불러오지 못함`, `예매 때와 계정 확인 상태가 다름`,
`비슷하거나 중복된 기록을 하나로 특정하지 못함`, `목록은 읽었지만 상태를 확정할 정보가 부족함`으로 나눠
표시합니다. 배포 전 기록처럼 근거가 없는 경우만 일반 `판단 불가`로 남습니다.
`요청 결과 불명확`은 예약 전달이나 성립을 단정하는 문구가 아닙니다. 카드의 `예약 요청` 단계가 완료됐으면
예매 명령 뒤 결과를 확정하지 못한 것이고, 그 단계가 없으면 전달 여부 자체도 불명확한 것입니다. 특히 요청
단계 뒤 로그인 필요·운영사 차단이 나타나면 로그인 확인 뒤에도 같은 예매를 다시 보내지 않고 공식 예약 내역만
읽습니다. 요청 단계 전의 인증 실패만 새 예약 시도와 분리된 로그인 복구 대상으로 다룹니다.
SRT는 단발 예약 직후 요청한 승객 수만큼의 호차·좌석번호를 모두 확인하지 못하면, 같은 여정의 기존 예약과
구분할 수 없으므로 `결제 필요`가 아니라 `요청 결과 불명확`으로 표시합니다. 결제 필요로 이미 확인된 예약의
후속 읽기에서도 저장된 좌석 전체 집합과 공식 record의 좌석 전체 집합이 정확히 같아야 미결제 상태를 유지하거나
결제 완료로 인정합니다. 원래 결과가 `요청 결과 불명확`이어도 단발 예약 결과에서 모든 승객의 정확한
호차·좌석을 얻어 비공개 상관 근거로 보존한 경우에는 공식 record의 여정·객실·인원·좌석 집합까지 비교합니다.
유일한 결제 완료 record는 활성 예매 준비·진행·감시 중 또는 결제 필요 작업을 완료하고, 사용 가능한 미결제
보류는 그때 확인된 좌석을 예약 좌석으로 표시합니다. 이런 상관 근거가 없는 일반 SRT `UNKNOWN`은 같은 여정의
paid·unpaid record만으로 완료나 보류를 확정하지 않습니다. KORAIL 결제보류는 레일웨잇에 저장한 예약 좌석과 같은 인증 session의 현재
발권 승차권에서 여정·객실·호차·좌석이
모두 일치해야 합니다. KORAIL의 `요청 결과 불명확`도 예약 요청 뒤 브라우저 보존 상태에서 얻은 정확한 좌석
상관 근거가 별도 저장되고 유일한 공식 발권 승차권과 일치한 경우에만 완료합니다. KORAIL 미결제 예약 목록에는
이 좌석을 검증할 정보가 없으므로 `UNKNOWN`을 결제 필요로 바꾸지 않습니다. 비공개 상관 근거는 불확실한 동안
화면의 예약 좌석이나 API·알림에 표시하지 않습니다. 상관 좌석을 저장하지 못한 기존 시도는 같은 여정의 과거
승차권과 구분할 수 없으므로 발권 카드와 미결제 예약 목록의 대상 부재가 함께 보여도 완료로 추정하지 않습니다.
미결제 보류가 남아 있거나 목록이 비었는지 신뢰할 수 없고, 발권 카드가 중복·불완전해도 완료로 보지 않습니다.
결제 뒤에도 공식 앱·홈페이지에서 최종 상태를 확인하세요.

앞선 결과가 `요청 결과 불명확`이어도 위 좌석 상관 근거와 운영사별 exact 조건을 모두 만족하는 결제 완료가
유일하게 확인되면 활성 예매 준비·진행·감시 중 또는 결제 필요 작업과 재시도는 완료로 끝납니다. 반대로 좌석
상관 근거가 없는 KORAIL·SRT 시도, `판단 불가`, 대상 부재만으로는 완료 또는 실패를 추정하지 않습니다.

새 결제 판정이 배포되기 전에 재확인 횟수를 모두 사용했거나 결제기한 뒤 이미 감시로 복귀한 과거 시도는
자동으로 소급 완료되지 않습니다. 특히 해당 시도에 호차·좌석이 저장되지 않았다면 현재 유효한 발권 승차권과
후속 예약 부재가 함께 보여도 완료로 추정하지 않으며, 이 경우 공식 승차권 화면을 기준으로 확인해야 합니다.

종료된 결제보류이거나 `UNKNOWN` 공식 확인이 세 번 이상 계속 불명확하면 홈에 `자동 예매 다시 시도`가 표시될 수 있습니다. 여러 열차 후보가 있어도 버튼과 대화상자는 서버가 유일하게 수동 재개 대상으로 정한 원래 시도의 열차를 표시하며, 대상을 하나로 확정할 수 없으면 버튼을 표시하지 않습니다. `UNKNOWN`에서는 대화상자에 적힌 정확한 열차·날짜·출발시각·좌석등급을 공식 앱 또는 홈페이지의 예약·승차권 목록에서 확인하고, 해당 예약이 없다는 확인란을 직접 선택해야 합니다. 버튼을 누르는 것만으로 예약하지 않으며 자동 공식 내역 확인도 여섯 번째까지 계속됩니다. 확인 뒤 새로 받은 같은 원본 후보의 공식 `좌석 있음`·`매진 임박` 관측에서만 한 번 시도하고, 다른 후보에 좌석이 나와도 미확인 예약 결과를 우회하지 않습니다. 그 사이 어느 후보에서든 예약이나 결제 상태가 확인되면 시도하지 않습니다. 매진·입석만 가능·판단 불가 관측에서는 감시를 유지하며, 수동 재개 결과가 다시 불명확해도 같은 예외를 연쇄 적용하지 않습니다. 결제는 여전히 공식 플랫폼에서 직접 진행합니다.

## 알림

설정 화면에서 알림 채널을 연결할 수 있습니다.

- 브라우저 푸시 알림
- Telegram
- Discord
- Webhook

연결한 채널은 이후 발생하는 알림에 적용됩니다. 실제 외부 채널 수신은 운영 환경에서 직접 시험해야 합니다.

좌석 발견·예매 진행·결제·감시 복귀 알림에는 확인된 후보의 운영사, 열차번호, 날짜, 구간, 실제 출도착 시각과 좌석 등급을 함께 표시합니다. 결제 필요 결과에는 운영사 결과에서 호차와 좌석번호를 모두 확인한 배정 좌석도 표시합니다. 예매 결과 알림에는 시도 순서와 시작·종료 시각, 다음 자동 예매 조건처럼 비밀값이 아닌 작업 흐름 정보도 포함합니다. 열차 후보나 배정 좌석을 정확히 연결할 근거가 없는 이벤트는 임의 값을 추정하지 않습니다.

Web Push는 기기마다 따로 연결합니다. 현재 기기가 연결되지 않았으면 로그인 뒤 어느 화면에서든 하단에 `OS 알림 켜기`가 나타납니다. 설정 화면으로 이동할 필요 없이 이 버튼을 누르면 브라우저 권한 요청과 현재 기기 연결을 이어서 진행합니다. 브라우저는 알림 권한을 직접 사용자 행동에서만 요청하도록 제한하므로 페이지를 열었다는 이유만으로 승인창을 강제로 띄우지는 않습니다. 권한을 이미 차단했다면 브라우저의 사이트 권한에서 다시 허용해야 합니다. 사용자가 앱에서 OS 알림을 직접 끈 기기에는 전역 연결 안내를 다시 표시하지 않습니다.

연결 뒤 설정에는 현재 기기의 상태와 전체 활성 기기 수가 함께 표시됩니다. 현재 기기에서 알림을 끄더라도 다른 브라우저와 기기의 구독은 유지됩니다. `시험` 버튼은 지금 사용 중인 기기로만 보내므로 각 기기에서 한 번씩 확인하세요. 만료된 구독은 해당 기기만 비활성화되며 다른 활성 기기의 알림을 중단하지 않습니다.

Web Push와 접속 중 `실시간 알림`은 표시 위치와 역할이 다릅니다.

- Web Push는 앱이 백그라운드이거나 닫혀 있을 때 Windows 시스템 알림, Android 알림창 또는 Apple 알림센터에 표시됩니다. 같은 대기의 다음 단계 알림은 가능한 경우 기존 알림을 갱신합니다.
- 앱을 사용 중일 때 Push가 도착하면 현재 대기 목록을 다시 확인한 뒤 `실시간 알림`에 최신 상태를 반영합니다. Android·iPhone·iPad에서 같은 상단 간략 팝업을 8초간 보여 주고 이후 접힌 알림 건수에 남깁니다. `자세히`를 눌러 전체 목록을 볼 수 있으며, 팝업은 페이지 스크롤이나 현재 입력을 막지 않습니다. 8초가 지나면 간략 팝업만 접히고 알림은 남지만, 팝업의 X 또는 펼친 알림·그룹의 닫기를 누르면 해당 알림을 실제로 제거합니다. 명시적으로 닫은 중요 알림은 같은 브라우저에 제한적으로 기록되므로 재접속해도 동일하거나 더 오래된 상태가 다시 몰려오지 않고, 같은 작업의 더 새로운 상태만 다시 알립니다. 다른 브라우저·기기와 닫기 기록을 동기화하지는 않습니다. 앱을 다시 열었을 때도 사용자가 닫지 않은 예매 진행·결제 필요·인증 필요·결과 불명 상태와 이미 확인된 세부 단계를 복원합니다. 현재 예매 진행 카드는 결과 상태로 바뀌거나 사용자가 닫을 때까지 자동으로 사라지지 않으며, 중단된 시도는 수동 확인 카드로 교체됩니다. 출발시간이 지나 감시가 종료된 작업은 `감시는 계속됩니다`라고 표시하지 않고 공식 결과 수동 확인만 안내합니다. Push payload만으로 좌석이나 예약 상태를 확정하지 않습니다.
- 자동 예매 결과가 도착하면 로그인 세션 확인, 검색 결과·열차 재확인, 객실 등급 선택, 예약 요청, 공식 결과 확인의 실제 시각을 표시합니다. `객실 등급 선택`은 일반실·특실 운임 control을 누른 단계이며 호차·좌석번호를 고른 것이 아닙니다. 각 줄의 `이전 단계 후` 시간과 카드의 `전체` 시간을 비교하면 공식 결과 페이지 이동이 느렸는지 예매 클릭 뒤 응답이 느렸는지 구분할 수 있습니다. 실행 중에는 아직 확인되지 않은 세부 단계나 완료시간을 추정하지 않습니다.
- 모바일 상단의 종 버튼은 같은 `실시간 알림`을 펼칩니다. 현재 남아 있는 알림 건수는 버튼 배지에 표시되며, 새 알림이 없어도 빈 상태를 확인할 수 있습니다. 알림센터는 대화상자가 아니므로 화면 스크롤과 현재 작업을 잠그지 않습니다.
- KORAIL 자동 예매 중에는 실제로 확인된 `로그인 세션 확인`, `검색 결과·열차 재확인`, `객실 등급 선택`, `예약 요청` 단계가 같은 진행 카드에 차례로 추가됩니다. 아직 발생하지 않은 단계나 완료시간은 미리 만들지 않습니다. 아주 빠르게 연속된 단계는 한 화면 갱신에 함께 보일 수 있으며, 현재 대기 단계의 원형 표시는 결과가 올 때까지 계속 회전합니다. 최종 실시간 이벤트를 놓쳐도 다음 대기 목록 갱신에서 완료된 최신 시도의 결과를 확인해 진행 카드를 좌석 소실·실패·수동 확인 카드로 교체합니다. 모션 감소 설정을 켠 기기에서는 접근성 설정에 따라 회전하지 않습니다.
- 현재 adapter가 예약 명령 전달 전에 종료됐음을 명시해 반환한 `철도사 연결 불가` 결과는 예약 전 준비 실패로
  표시합니다. 이 경우 `예약 요청`이나 `공식 결과 확인`을 완료한 것처럼 만들지 않으며 공식 예약 내역 수동 확인도
  요구하지 않습니다. 이전 버전이 전달 여부를 구분하지 못한 채 저장한 같은 모양의 결과는 업데이트 과정에서
  `결과 불명확`으로 보수 전환해 자동 재예매를 막고 공식 내역을 다시 확인합니다.
- 철도사 호출 중 응답이 끊겨 예약 명령 전달 여부를 확인할 수 없는 경우에는 단순 실패로 끝내지 않습니다.
  자동 재예매를 막은 `결과 불명확` 상태에서 공식 예약 내역을 읽기 전용으로 확인하며, 실제로 확인된 진행
  단계만 표시합니다.
- 공식 대상 부재 확인 뒤 허용된 자동 복구 1회까지 사용한 시도는 `추가 자동 예매 차단` 근거를 활동 행에
  표시합니다. 좌석이 다시 보이더라도 이 복구 결과를 재귀적으로 반복하지 않으며, 새로 만든 별도 작업이나 다른
  후보의 정상 최초 시도와 혼동하지 않습니다. 공식 부재가 확인된 현재 결과 자체는 수동 확인 필요 상태가
  아니므로 이전의 `공식 예매 내역 확인` 경고를 계속 표시하지 않습니다.
- 진행 스트림 연결이 중간에 끊겨도 예약 명령을 자동으로 다시 보내지 않습니다. 이미 예약 클릭이 실행됐을 가능성이 있으므로 결과를 확정하지 못한 작업은 수동 확인이 필요한 불확실 상태로 처리하고 공식 예약 목록 확인 흐름을 사용합니다.
- 알림을 누르면 외부 철도사 페이지를 바로 열지 않고, 열려 있는 레일웨잇 화면을 앞으로 가져오거나 PWA 시작 화면을 새로 엽니다. 종료된 앱을 여는 경우 캐시된 화면과 정적 파일을 먼저 사용해 첫 표시를 앞당기고 백그라운드에서 새 버전을 확인합니다. 로그인 상태와 최신 대기 데이터는 서버 응답 뒤 반영됩니다.
- 화면 위 팝업 알림은 Android 알림 중요도, `화면에 팝업 표시`, 방해 금지, 알림 쿨다운 설정에 따라 달라집니다. PWA가 표시를 강제할 수는 없습니다.
- 레일웨잇은 좌석 발견·예매 진행·결제·인증과 같은 중요 상태를 높은 Web Push 전달 우선순위로 보내고 진동 힌트를 요청합니다. 시험 알림도 실제 중요 상태와 같은 `status: seat_found` envelope로 이 경로를 확인합니다. 웹은 알림 소리를 직접 지정할 수 없고, 진동 힌트도 기기에서의 동작을 보장하지 않습니다. 알림창에는 오지만 소리·진동이나 화면 위 팝업이 없으면 방금 받은 알림을 길게 눌러 해당 브라우저 알림 채널의 팝업·소리·진동 허용 여부를 확인하고, Android 15 알림 쿨다운을 끈 뒤 2분 이상 간격으로 다시 시험하세요.
- 위 설정이 모두 켜진 상태에서도 알림창에만 도착한다면 Chrome이 만든 사이트 채널의 한계입니다. Web Push나 설치형 PWA는 채널 중요도를 직접 올릴 수 없으며, 레일웨잇은 별도 APK 없이 알림창 수신과 앱 사용 중 상단 `실시간 알림`을 지원 범위로 둡니다.
- iOS·iPadOS는 16.4 이상에서 홈 화면에 설치한 PWA만 Web Push를 지원합니다. Apple의 배너 스타일과 Focus는 운영체제·사용자 설정이 결정하며 PWA가 Time Sensitive나 Critical 표시를 강제할 수 없습니다. 앱 사용 중에는 위 레일웨잇 상단 팝업이 플랫폼과 무관하게 표시됩니다.

## 공식 플랫폼으로 이동하기

좌석 확인이나 결제가 필요하면 공식 앱·홈페이지에서 다시 확인할 수 있도록 여정 정보를 정리해 줍니다.

- 공식 페이지가 자동으로 좌석을 확보했다고 보지 않습니다.
- 공식 페이지를 열었다는 이유만으로 예약 성공으로 처리하지 않습니다.
- 결제기한이 제공되지 않으면 임의의 남은 시간을 만들지 않습니다.
- 배정 좌석은 운영사 예약 결과에서 호차와 좌석번호를 모두 확인한 경우에만 표시하며, 표시가 없으면 공식 예약 내역에서 확인합니다.
- 결제는 사용자가 직접 진행합니다.
- 기본 설정에서는 브라우저 탭과 설치형 PWA 모두 공식 HTTPS를 새 브라우저 창으로 엽니다. 좌석 확인·예매는 운영사 예매 페이지로, `결제 필요`와 예약 확인은 코레일 예약목록 또는 SRT 발권·취소 조회 페이지로 이동합니다. 레일웨잇 PWA 화면을 공식 홈페이지로 바꾸는 JavaScript 타이머 fallback은 사용하지 않습니다.
- 코레일+ 7.0.0에서 예매·승차권 BROWSABLE 경로가 확인됐으며, Chrome 설치형 PWA의 예매 클릭은 실제 예매 화면, 승차권 경로는 비로그인 로그인 화면까지 이동했습니다. 로그인 뒤 미결제 목록은 아직 운영 확인 항목입니다.
- SRT 2.0.41에서 `srapp://main`은 콜드 실행 시 승차권 예매 홈으로, 같은 공개 진입점에 고정 문자열 extra `btnNo=2`를 전달한 경로는 PWA 클릭에서도 `승차권 확인` 화면으로 이동했습니다. 이미 SRT의 다른 화면이 열린 웜 실행에서 main은 예매 홈을 보장하지 않으므로 main과 ticket을 독립 플래그로 관리합니다.
- SRT 앱이 이미 실행 중이면 `승차권 확인` 화면만 열리고 방금 예약 목록은 즉시 갱신되지 않을 수 있습니다. 결제 카드의 안내대로 앱 하단 `승차권 확인`을 한 번 더 누르면 앱 내부 조회가 다시 실행됩니다.
- 앱이 없거나 resolver가 연결하지 못하면 브라우저가 고정 HTTPS fallback을 외부 Custom Tab으로 열고 레일웨잇 PWA는 유지합니다. 레일웨잇은 설치 여부나 실행 성공을 판정하지 않으며, WebView 기반 인앱 브라우저·다른 브라우저·iOS는 공식 HTTPS를 사용합니다.

## 설정

설정 화면에서는 다음 항목을 관리합니다.

- 철도 계정
- 알림 채널
- 실시간 화면 동기화 상태
- 좌석 확인 주기
- 로그와 진행 상태

화면 표시는 `실시간`으로 고정되어 별도의 초 값을 설정하지 않습니다. 중요 상태·예약 이벤트와 Push·수동 갱신은 최신 대기 목록을 바로 읽어 React 화면에 반영하고, 반복되는 좌석 관측 이벤트는 다음 내부 5초 자동 조회에 합칩니다. 이 조회는 놓친 이벤트도 복구합니다. 새 대기 열차 목록도 5초마다 서버에 저장된 마지막 정상 snapshot을 동기화하며, 이 과정 자체가 철도사 조회를 같은 간격으로 만들지는 않습니다. 탭이 보이지 않는 동안에는 정기 갱신과 이벤트별 상태 투영을 생략하고 무효화만 한 건으로 접은 뒤, 다시 보일 때 최신 상태를 한 번 읽습니다. 결제기한 시계와 설정 화면의 런타임 조회도 숨김 상태에서는 멈추고 복귀할 때 즉시 갱신합니다.

최신 대기 목록을 정상적으로 읽은 뒤 이전 목록에 있던 작업이 24시간 복구 범위를 지나 빠졌다면, 그 작업에 남아 있던 고정 알림만 현재 열린 화면에서 정리합니다. 이를 작업 완료나 실패로 추정하지 않으며, 사용자가 알림을 닫은 것으로 저장하지도 않습니다. 전체 이력은 `내 예약`에서 계속 확인할 수 있습니다.

사용자가 설정하는 좌석 관측 목표는 1~600초이고 기본값은 5초입니다. 1초까지 저장할 수 있지만 정확한 1초 주기를 보장하는 값은 아닙니다. 작업자 처리량, 운영사별 단일 실행, 브라우저 응답시간, cache, 실패 backoff와 보호 cooldown이 우선하므로 실제 시작은 더 늦을 수 있습니다. 연속 1초 조회는 운영사 보호 응답 위험도 높으므로 일반 운영에서는 기본 5초를 권장합니다.

홈에서 실제 좌석 조회가 시작된 작업은 `좌석 관측 중`으로 표시합니다. 중복 실행 방지를 위해 작업자가 내부에 잡아 둔 임시 만료 시각은 사용자에게 다음 관측 예정 시각으로 표시하지 않습니다. 관측이 끝나면 `다음 좌석 관측 목표` 시각을 다시 표시하며, `최근 확인`과 다음 목표는 모두 초 단위로 표시합니다. 실제 시작 시각은 작업자 처리량과 운영사별 단일 실행, lease, cache, backoff, cooldown에 따라 목표보다 늦어질 수 있습니다.

`로그·진행 상태`의 최근 진행 기록은 최근 24시간의 작업 흐름과 확인이 필요한 오류 중 최신 20건을 보여
줍니다. 매진·예약 가능·잔여석 부족처럼 반복되는 정상 좌석 관측은 목록에서 제외하고, 좌석 조회 오류·확인
불가·자료 만료, 공식 확인의 닫힌 판단 불가 원인, 로그인 확인 필요, 운영사 요청 제한, 대기 상태 변경, 예매·알림 처리, 결제보류 종료·감시
복귀·일회성 종료·공식 결제 완료를 표시합니다. 정상 관측을 목록에서 제외해도 전체 좌석 관측 수와 오류율
집계에는 계속 반영됩니다. 근거가 있는 행에는 열차번호, 운행일의 월·일·요일과 출발시각, 좌석등급을 함께
표시합니다. 내부 watch/candidate ID, 노선 원문, provider 오류 원문과 비밀값은 표시하지 않으며, 영속되지 않은
계정 저장 요청 실패나 저장되지 않은 세부 실패 원인은 이 목록에 항상 남지 않습니다.

## 문제가 생겼을 때

먼저 설정의 `로그·진행 상태`에서 현재 상태를 확인하세요. 원문 비밀번호나 토큰은 화면에 표시되지 않습니다.

서비스가 시작되지 않거나 알림이 오지 않으면 [설치·운영 가이드](OPERATIONS.md#문제-해결)를 참고하세요.
