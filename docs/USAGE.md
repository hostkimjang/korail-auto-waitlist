# 사용 안내

레일웨잇의 기본 사용 흐름을 설명합니다. 화면에 표시되는 좌석과 예약 정보는 공식 앱이나 홈페이지에서 최종 확인해야 합니다.

## 새 대기 만들기

1. 메뉴에서 `새 대기`를 선택합니다.
2. KTX 또는 SRT를 고릅니다. 두 운영사를 함께 선택할 수도 있습니다.
3. 출발역, 도착역, 출발일과 시간 범위를 정합니다.
4. 관심 열차의 일반실 또는 특실을 선택합니다.

열차와 좌석 등급마다 대기가 하나씩 만들어집니다. 같은 열차의 일반실과 특실을 각각 등록할 수 있습니다.

모바일과 터치 태블릿에서는 출발역과 도착역을 전용 전체 화면에서 연속으로 고릅니다. 먼저 주요 역이나 지역을 탐색할 수 있고, 검색창을 누르면 가상 키보드가 열린 높이에 맞춰 결과 영역만 줄어듭니다. 출발역을 고르면 도착역 선택으로 이어지며, 선택 결과는 공식 역 ID와 함께 원래 여정 화면에 반영됩니다.

시간대 빠른 선택의 `새벽`은 `00:00–09:00`, `저녁`은 `18:00–00:00` 범위입니다. 저녁의 `00:00`은 선택한 출발일의 다음 자정을 뜻하며, 화면과 음성 안내에서 다음 날 경계임을 구분합니다.

## 홈 화면

홈에서는 지금 확인해야 할 항목과 감시 중인 대기를 볼 수 있습니다.

- `감시 중`: 좌석 상태 변화를 확인하고 있습니다.
- `좌석 확인 필요`: 최근 상태를 확정할 정보가 없습니다.
- `좌석 발견`: 공식 앱이나 홈페이지에서 다시 확인할 시점입니다.
- `결제 필요`: 예매 시도 결과 결제가 필요한 것으로 확인된 상태입니다. 실제 예약 내역과 결제기한은 공식 앱이나 홈페이지에서 확인하세요.
- `인증 필요`: 저장한 철도 계정의 로그인을 다시 확인해야 합니다.

정보가 오래됐거나 근거가 충분하지 않으면 `좌석 확인 필요`로 표시합니다.

## 대기 관리

감시 중인 항목에서 다음 작업을 할 수 있습니다.

- 잠시 멈추기
- 다시 시작하기
- 대기 취소하기
- 좌석을 발견했을 때 할 일 변경하기

`알림만 받기`는 상태가 바뀌었을 때 알려주고 감시를 계속합니다. 실험 기능과 철도 계정 설정을 모두 마친 경우에만 제한적인 예매 시도 옵션을 사용할 수 있습니다. 자동 예매는 같은 좌석 가용 상태에서 한 번만 실행하며, 예매 시점에 좌석을 확보하지 못한 경우에는 확정적인 판매 불가 상태 뒤 좌석이 다시 가용해져야 다음 시도를 시작합니다. 결과가 불확실하면 자동 반복하지 않고 공식 예약 내역 확인을 안내합니다.

## 알림

설정 화면에서 알림 채널을 연결할 수 있습니다.

- 브라우저 푸시 알림
- Telegram
- Discord
- Webhook

연결한 채널은 이후 발생하는 알림에 적용됩니다. 실제 외부 채널 수신은 운영 환경에서 직접 시험해야 합니다.

Web Push는 기기마다 따로 연결합니다. 현재 기기가 연결되지 않았으면 로그인 뒤 어느 화면에서든 하단에 `OS 알림 켜기`가 나타납니다. 설정 화면으로 이동할 필요 없이 이 버튼을 누르면 브라우저 권한 요청과 현재 기기 연결을 이어서 진행합니다. 브라우저는 알림 권한을 직접 사용자 행동에서만 요청하도록 제한하므로 페이지를 열었다는 이유만으로 승인창을 강제로 띄우지는 않습니다. 권한을 이미 차단했다면 브라우저의 사이트 권한에서 다시 허용해야 합니다. 사용자가 앱에서 OS 알림을 직접 끈 기기에는 전역 연결 안내를 다시 표시하지 않습니다.

연결 뒤 설정에는 현재 기기의 상태와 전체 활성 기기 수가 함께 표시됩니다. 현재 기기에서 알림을 끄더라도 다른 브라우저와 기기의 구독은 유지됩니다. `시험` 버튼은 지금 사용 중인 기기로만 보내므로 각 기기에서 한 번씩 확인하세요. 만료된 구독은 해당 기기만 비활성화되며 다른 활성 기기의 알림을 중단하지 않습니다.

Web Push와 접속 중 `실시간 알림`은 표시 위치와 역할이 다릅니다.

- Web Push는 앱이 백그라운드이거나 닫혀 있을 때 Windows 시스템 알림, Android 알림창 또는 Apple 알림센터에 표시됩니다. 같은 대기의 다음 단계 알림은 가능한 경우 기존 알림을 갱신합니다.
- 앱을 사용 중일 때 Push가 도착하면 현재 대기 목록을 다시 확인한 뒤 `실시간 알림`에 최신 상태를 반영합니다. Android·iPhone·iPad에서 같은 상단 간략 팝업을 8초간 보여 주고 이후 접힌 알림 건수에 남깁니다. `자세히`를 눌러 전체 목록을 볼 수 있으며, 팝업은 페이지 스크롤이나 현재 입력을 막지 않습니다. 앱을 다시 열었을 때도 서버에 남아 있는 예매 진행·결제 필요·인증 필요 상태를 복원하며, 현재 예매 진행 카드는 결과 상태로 바뀌거나 사용자가 닫을 때까지 자동으로 사라지지 않습니다. Push payload만으로 좌석이나 예약 상태를 확정하지 않습니다.
- 알림을 누르면 외부 철도사 페이지를 바로 열지 않고, 열려 있는 레일웨잇 화면을 앞으로 가져오거나 PWA 시작 화면을 새로 엽니다. 종료된 앱을 여는 경우 캐시된 화면과 정적 파일을 먼저 사용해 첫 표시를 앞당기고 백그라운드에서 새 버전을 확인합니다. 로그인 상태와 최신 대기 데이터는 서버 응답 뒤 반영됩니다.
- 화면 위 팝업 알림은 Android 알림 중요도, `화면에 팝업 표시`, 방해 금지, 알림 쿨다운 설정에 따라 달라집니다. PWA가 표시를 강제할 수는 없습니다.
- 레일웨잇은 좌석 발견·예매 진행·결제·인증과 같은 중요 상태를 높은 Web Push 전달 우선순위로 보내고 진동 힌트를 요청합니다. 시험 알림도 실제 중요 상태와 같은 `status: seat_found` envelope로 이 경로를 확인합니다. 웹은 알림 소리를 직접 지정할 수 없고, 진동 힌트도 기기에서의 동작을 보장하지 않습니다. 알림창에는 오지만 소리·진동이나 화면 위 팝업이 없으면 방금 받은 알림을 길게 눌러 해당 브라우저 알림 채널의 팝업·소리·진동 허용 여부를 확인하고, Android 15 알림 쿨다운을 끈 뒤 2분 이상 간격으로 다시 시험하세요.
- 위 설정이 모두 켜진 상태에서도 알림창에만 도착한다면 Chrome이 만든 사이트 채널의 한계입니다. Web Push나 설치형 PWA는 채널 중요도를 직접 올릴 수 없으며, 레일웨잇은 별도 APK 없이 알림창 수신과 앱 사용 중 상단 `실시간 알림`을 지원 범위로 둡니다.
- iOS·iPadOS는 16.4 이상에서 홈 화면에 설치한 PWA만 Web Push를 지원합니다. Apple의 배너 스타일과 Focus는 운영체제·사용자 설정이 결정하며 PWA가 Time Sensitive나 Critical 표시를 강제할 수 없습니다. 앱 사용 중에는 위 레일웨잇 상단 팝업이 플랫폼과 무관하게 표시됩니다.

## 공식 플랫폼으로 이동하기

좌석 확인이나 결제가 필요하면 공식 앱·홈페이지에서 다시 확인할 수 있도록 여정 정보를 정리해 줍니다.

- 공식 페이지가 자동으로 좌석을 확보했다고 보지 않습니다.
- 공식 페이지를 열었다는 이유만으로 예약 성공으로 처리하지 않습니다.
- 결제기한이 제공되지 않으면 임의의 남은 시간을 만들지 않습니다.
- 결제는 사용자가 직접 진행합니다.
- 기본 설정에서는 브라우저 탭과 설치형 PWA 모두 공식 HTTPS를 새 브라우저 창으로 엽니다. 좌석 확인·예매는 운영사 예매 페이지로, `결제 필요`와 예약 확인은 코레일 예약목록 또는 SRT 발권·취소 조회 페이지로 이동합니다. 레일웨잇 PWA 화면을 공식 홈페이지로 바꾸는 JavaScript 타이머 fallback은 사용하지 않습니다.
- 코레일+ 7.0.0에서 예매·승차권 BROWSABLE 경로가 확인됐으며, Chrome 설치형 PWA의 예매 클릭은 실제 예매 화면, 승차권 경로는 비로그인 로그인 화면까지 이동했습니다. 로그인 뒤 미결제 목록은 아직 운영 확인 항목입니다.
- SRT 2.0.41에서 `srapp://main`은 콜드 실행 시 승차권 예매 홈으로, 같은 공개 진입점에 고정 문자열 extra `btnNo=2`를 전달한 경로는 PWA 클릭에서도 `승차권 확인` 화면으로 이동했습니다. 이미 SRT의 다른 화면이 열린 웜 실행에서 main은 예매 홈을 보장하지 않으므로 main과 ticket을 독립 플래그로 관리합니다.
- SRT 앱이 이미 실행 중이면 `승차권 확인` 화면만 열리고 방금 예약 목록은 즉시 갱신되지 않을 수 있습니다. 결제 카드의 안내대로 앱 하단 `승차권 확인`을 한 번 더 누르면 앱 내부 조회가 다시 실행됩니다.
- 앱이 없거나 resolver가 연결하지 못하면 브라우저가 고정 HTTPS fallback을 외부 Custom Tab으로 열고 레일웨잇 PWA는 유지합니다. 레일웨잇은 설치 여부나 실행 성공을 판정하지 않으며, WebView 기반 인앱 브라우저·다른 브라우저·iOS는 공식 HTTPS를 사용합니다.

## 설정

설정 화면에서는 다음 항목을 관리합니다.

- 철도 계정
- 알림 채널
- 화면 갱신 주기
- 좌석 확인 주기
- 로그와 진행 상태

화면 갱신 주기를 짧게 설정해도 철도사 조회가 같은 간격으로 늘어나지는 않습니다. 철도사의 호출 제한과 보호 안내가 설정값보다 우선합니다.

## 문제가 생겼을 때

먼저 설정의 `로그·진행 상태`에서 현재 상태를 확인하세요. 원문 비밀번호나 토큰은 화면에 표시되지 않습니다.

서비스가 시작되지 않거나 알림이 오지 않으면 [설치·운영 가이드](OPERATIONS.md#문제-해결)를 참고하세요.
